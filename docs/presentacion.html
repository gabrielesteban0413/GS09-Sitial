Contexto

Elegir un framework backend
es una decisión de arquitectura

La elección condiciona el rendimiento, la velocidad de desarrollo, los costos de infraestructura y la capacidad de escalar. No es una preferencia personal.

Un framework inadecuado puede multiplicar por 10 los costos de servidores y retrasar el lanzamiento varios meses.
02 / 10
Framework seleccionado

Node.js

Runtime de JavaScript del lado del servidor, construido sobre el motor V8 de Chrome. Su modelo de concurrencia basado en un event loop no bloqueante permite manejar miles de conexiones simultáneas con un solo hilo.

Conclusión

Node.js fue
la decisión correcta

El proyecto consulta tres APIs externas cuyo tiempo promedio es 400 ms. Un framework síncrono bloquearía un worker completo durante ese tiempo. Con Node.js, el servidor atiende cientos de análisis concurrentes con hardware mínimo.

✓ Alto rendimiento ✓ Async nativo ✓ TypeScript compartido ✓ Escalable
